Google Drive API v3 Setup Guide

Step-by-step instructions for Service Account, OAuth2, and Folder Sharing

Why Service Account is Recommended for Enterprise Servers

Service accounts represent non-human server identities. They run completely unattended via Linux systemd timers or Windows Scheduled Tasks without prompting for interactive logins or expiring browser sessions.

1
Open Google Cloud Console & Create a Project

Visit https://console.cloud.google.com/. Log in with your Google account. Click the project dropdown at the top > click New Project. Name it (e.g. Enterprise-Backup-System) and click Create.

2
Enable Google Drive API v3

Navigate to APIs & Services > Library in the left sidebar. In the search box, type Google Drive API. Click on it and click the blue Enable button.

3
Create a Service Account

Navigate to APIs & Services > Credentials. Click + CREATE CREDENTIALS at the top > select Service Account.

  • Service account name: e.g. backup-operator
  • Service account ID: auto-filled (e.g. backup-operator@your-project-id.iam.gserviceaccount.com)
  • Click CREATE AND CONTINUE, and then click DONE.
4
Generate and Download the JSON Key File

In the Credentials screen, locate your newly created service account under the Service Accounts table. Click on its email address. Then:

  1. Click on the Keys tab at the top.
  2. Click ADD KEY > Create new key.
  3. Select JSON as the key type. Click CREATE.
  4. A file named something like your-project-xxxx.json will automatically download to your computer.
5
Position the JSON File on your Server

Copy the downloaded file to your backup server directory (or secure system directory like /etc/backup_service/). For example:

./service_account.json   # (relative to server root)
/etc/backup_service/service_account.json   # (or absolute path)

Enter this exact path into the Service Account Key File Path field.

🚨 Crucial Google Architecture Notice: Folder Sharing

Unlike human Google accounts, a Service Account has its own isolated, empty virtual drive without a personal Google Drive UI. If you do not share your Google Drive folder with the Service Account email, backups will fail with 404 File Not Found!

1
Copy the Service Account Email

Open your downloaded service_account.json file or check Google Cloud Console Credentials. Look for the "client_email" attribute, which looks like:

backup-operator@enterprise-backup-system.iam.gserviceaccount.com
2
Create the Root Backup Folder in Google Drive

Go to your personal or Google Workspace Drive (https://drive.google.com). Click + New > New Folder. Name it exactly:

STAR_Enterprise_Backups
3
Share the Folder with Editor Permission
  1. Right-click the newly created STAR_Enterprise_Backups folder.
  2. Select Share > Share.
  3. Paste the Service Account email in the Add people and groups box.
  4. Make sure the role dropdown is set to Editor (Viewer is read-only and will cause writes to fail).
  5. Uncheck the Notify people box (service accounts do not have inboxes).
  6. Click Share.
Ready! Now your enterprise backup engine can stream compressed databases and directory snapshots directly into your Google Drive securely!

Understanding the Root Backup Folder Hierarchy

The Root Backup Folder Name (default: STAR_Enterprise_Backups) acts as the enterprise top-level storage container. The service maintains an isolated, uniform directory layout for each tenant client:

STAR_Enterprise_Backups/
├── client_tenant_1/
│ ├── daily/
│ │ ├── 2026-11-10/ # (daily incremental snapshot)
│ │ │ ├── db_starcalibration.sql.gz
│ │ │ ├── folder_uploads.tar.gz
│ │ │ └── manifest.json
│ │ ├── 2026-11-11/
│ │ └── 2026-11-12/
│ ├── master/ # (cumulative master snapshot)
│ │ ├── db_starcalibration.sql.gz
│ │ └── folder_uploads.tar.gz
│ └── audit_manifest_2026-11-12.txt # (OWASP mutation audit log)
└── client_tenant_2/
    └── ...
10-Day Retention Window

The sliding retention window automatically prunes daily snapshots older than 10 days in the daily/ folder. The master/ directory is never deleted.

Zero-Deletion File Audit Log

Files removed from client servers are never deleted from remote backups; mutations are tracked with exact timestamps in audit_manifest.txt.

Reconnecting Existing Backups: If you ever reinstall this backup service or move to a new machine, you can simply register the same Root Backup Folder Name (STAR_Enterprise_Backups) to instantly discover and restore historical backups!

When to Choose OAuth2 Client Flow

Choose OAuth2 if your Google Workspace administrator restricts Service Accounts or if you are running this backup manager directly on your local workstation with interactive browser authorization.

1
Configure OAuth Consent Screen

In Google Cloud Console, navigate to APIs & Services > OAuth consent screen.

  • Select External (or Internal if in a Workspace organization).
  • Fill in App name (e.g. Star Enterprise Backup) and your user support email.
  • Under Scopes, add https://www.googleapis.com/auth/drive.
  • Under Test users, add your personal Gmail address and save.
2
Create OAuth 2.0 Client ID

Go to APIs & Services > Credentials > + CREATE CREDENTIALS > OAuth client ID.

  • Application type: Select Desktop app.
  • Name: Backup Desktop Client
  • Click CREATE.
3
Download and Rename Client Secret

Click DOWNLOAD JSON next to your new client ID. Rename the file to client_secret.json and place it in the project root directory.

4
Initial Authorization & Token Generation

During the first backup execution or health test, a browser window opens requesting permission. After approving, the authentication token is permanently saved to token.json.

Common Issues & Quick Fixes

Error: 404 File Not Found / Folder Not Accessible Cause: The Google Drive folder is not shared with the Service Account email.
Fix: Open Google Drive > right-click STAR_Enterprise_Backups > Share > paste your Service Account email (...iam.gserviceaccount.com) > give Editor rights.
Error: 403 Forbidden / Insufficient Permissions Cause: The Service Account was given "Viewer" or "Commenter" permission instead of "Editor".
Fix: Change the folder permission in Google Drive to Editor so the service can upload and create subdirectories.
Error: FileNotFoundError: ./service_account.json Cause: The path specified does not match the actual location of the key file on the server.
Fix: Use an absolute path like /etc/backup_service/service_account.json (on Linux) or C:/backup_service/service_account.json (on Windows). Ensure read permissions for the web server user.
