Multi-Cloud Storage Credential & Setup Guide

Step-by-step instructions to obtain API keys and configure storage destinations

Google Drive API v3 Configuration

Service Account • OAuth2
Recommended Mode: Use Service Account for automated server cron / systemd background jobs. Service accounts run without user browser popups and never expire.
1
Google Cloud Console Setup

Visit https://console.cloud.google.com/. Create a new project (e.g. Enterprise-Backup-System). Under APIs & Services > Library, search for Google Drive API and click Enable.

2
Create Service Account & Download JSON Key

Go to APIs & Services > Credentials > + CREATE CREDENTIALS > Service Account. Name it backup-operator and click Done. Click on the created service account email > go to Keys tab > Add Key > Create new key > JSON. Download the JSON key file.

Save to: /etc/backup_service/service_account.json (or ./service_account.json)
3
🚨 MANDATORY PERMISSION STEP: Share Drive Folder

Service Accounts do NOT have a personal Drive UI. You must grant them write permission into your Google Drive:

  1. Copy your Service Account email: ...iam.gserviceaccount.com
  2. In Google Drive ([drive.google.com](https://drive.google.com)), create a folder named STAR_Enterprise_Backups.
  3. Right-click the folder > Share > Paste the Service Account email.
  4. Set permission to Editor (uncheck "Notify people") > Click Share.
4
Alternative: OAuth2 Client Flow (Personal Use)

Go to APIs & Services > OAuth consent screen (External, add scope .../auth/drive, add your email to Test Users). Then under Credentials > OAuth client ID, choose Desktop app, download client_secret.json. On initial run, a browser sign-in generates token.json.

Microsoft OneDrive & SharePoint (Graph API)

Microsoft Entra ID / Azure AD
Authentication Flow: OneDrive connects via Microsoft Graph OAuth2 Client Credentials flow. Backups stream directly to OneDrive or SharePoint document libraries unattended.
1
Azure Portal App Registration

Go to the Azure Portal or Microsoft Entra admin center. Navigate to Microsoft Entra ID > App registrations > + New registration.

  • Name: LimsEnterpriseBackup
  • Supported account types: Select Accounts in any organizational directory and personal Microsoft accounts (or Single tenant for enterprise).
  • Click Register.
2
Copy Tenant ID and Client ID

On the App Overview screen, copy the following values into this console:

Application (client) ID: 4a2b91c0-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Directory (tenant) ID: common (or organizational UUID)
3
Create Client Secret (Key)

In the left sidebar, click Certificates & secrets > + New client secret.

  1. Description: backup-encryption-key. Expiration: 24 months.
  2. Click Add.
  3. ⚠️ CRITICAL: Immediately copy the string in the Value column. (Azure permanently hides this value once you navigate away!).
  4. Paste this into the Client Secret field in the storage configuration.
4
Grant Microsoft Graph API Permissions

Click API permissions > + Add a permission > Microsoft Graph:

  • Select Application permissions (for background unattended service) or Delegated permissions.
  • Search for and check: Files.ReadWrite.All
  • Search for and check: offline_access
  • Click Add permissions.
  • Click Grant admin consent for [Your Tenant] button.

AWS S3 / S3-Compatible & TeraBox Cloud

IAM • Least-Privilege • S3 Protocol
Broad Compatibility: This engine speaks native Amazon S3 API protocol. It works out-of-the-box with AWS S3, TeraBox S3, Wasabi Hot Cloud, MinIO on-premises, Backblaze B2, and Cloudflare R2.
1
Create S3 Bucket in AWS Console

Go to AWS S3 Console > click Create bucket.

  • Bucket name: e.g. my-enterprise-backups-lims (globally unique).
  • AWS Region: Choose your preferred region (e.g. us-east-1, eu-west-1, ap-south-1).
  • Block Public Access: Keep all 4 settings checked (keep bucket private).
  • Bucket Encryption: Enable Amazon S3-managed keys (SSE-S3).
  • Click Create bucket.
2
Create Dedicated IAM User & Access Keys

Go to AWS IAM Console > Users > Create user.

  1. Username: lims-backup-operator > Click Next.
  2. Permissions: Select Attach policies directly > choose AmazonS3FullAccess (or custom least-privilege policy below) > Create User.
  3. Click on the user name > go to Security credentials tab > click Create access key.
  4. Select Application running outside AWS > Create access key.
  5. Copy Access Key ID (e.g. AKIA...) and Secret Access Key.
3
Least-Privilege IAM Policy (Production Recommended)

For enterprise compliance, restrict IAM permissions strictly to your backup bucket:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
      "Resource": "arn:aws:s3:::my-enterprise-backups-lims"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:AbortMultipartUpload"
      ],
      "Resource": "arn:aws:s3:::my-enterprise-backups-lims/*"
    }
  ]
}
4
S3 Endpoint URLs for TeraBox & S3 Providers
Standard AWS S3: Leave field blank or set https://s3.amazonaws.com
TeraBox S3 Gateway: https://s3.terabox.com
Wasabi Hot Cloud: https://s3.wasabisys.com
MinIO Self-Hosted: http://192.168.1.100:9000

Local Filesystem & Network Attached Storage (NAS)

NFS • CIFS/SMB • NVMe / Direct Attached
Zero Cloud Cost Option: Ideal for air-gapped data centers, internal company NAS appliances (Synology, QNAP, TrueNAS), or local test environments.
1
Directory Creation & Linux Permissions

Ensure the target path exists and the backup service user has read & write permissions:

# Create storage directory
sudo mkdir -p /mnt/nas/backups

# Assign ownership to service user
sudo chown -R limsbackup:limsbackup /mnt/nas/backups

# Restrict permissions (owner read/write/exec, group read/exec)
sudo chmod -R 750 /mnt/nas/backups

2
Automated NAS Mount via /etc/fstab

To permanently mount a network storage volume on Linux reboot:

# NFS NAS Mount Example (/etc/fstab): 192.168.1.100:/volume1/backups  /mnt/nas/backups  nfs  defaults,rw,nosuid,hard  0  0
# SMB / CIFS Windows Share Mount (/etc/fstab): //192.168.1.100/backups  /mnt/nas/backups  cifs  username=backup_user,password=SecretPass,uid=starbackup,gid=starbackup  0  0
3
Windows Host Configuration

On Windows systems, provide an absolute drive path (e.g. D:/Enterprise_Backups) or a direct UNC network path (e.g. \\192.168.1.100\backups\star). Ensure the Windows user running Python has Full Control in folder Security Properties.
